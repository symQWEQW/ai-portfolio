# RAG 召回调优：从指标到实验（v2 重写）

> 基于某地 AI 预审项目的真实实验数据。本文所有数字来自仓库 [`RESULTS.md`](https://github.com/symQWEQW/preaudit-rag-engine/blob/master/RESULTS.md)（v2 评估重建），由 `run_eval.py` 现场跑出。
>
> **版本说明**：本文 v1 曾引用「500 字切片 Recall@5 = 1.000」作为结论，该数字现已**撤回**。原因见第 1 节——它不是模型效果，而是评测口径的算术必然。本版用重建后的 38 题 / 三档 k 数据重写。

## 1. 先撤回一个「满分」

旧评测：5 篇模拟政策文档、合计 1,473 字，15 道题。500 字切片时每篇文档刚好切成 1 个 chunk，**整个库只有 5 个 chunk**，而计分窗口是 `top-5`：

```
top-5 ⊇ 全部 5 个 chunk
⇒ 对任意问题，top-5 ∩ gold 是否为空只取决于 gold 是否非空
⇒ 15 题 gold 全非空 ⇒ HitRate@5 恒等于 1.000，与检索质量无关
```

`Recall@5 = 1.000` 同理（top-5 包含全部 chunk，自然包含全部 gold）。

**发现并撤回了被语料规模撑起来的满分读数** —— 这一步比多贴一个好看数字值钱。重建后的评测：

| | v1（旧，已作废） | v2（现行） |
|---|---|---|
| 语料 | 5 篇 / 1,473 字 | **16 篇 / 13,390 字 + 4 篇干扰 / 723 字** |
| 题库 | 15 题（gold 指文档） | **38 题**（gold 精确到文档，附原文依据） |
| k | 单一 k=10 检索、按 k=5 计分 | **k = 3 / 5 / 10 三档** |
| HitRate@5（500 字） | ~~1.000~~ | **0.974** |
| Recall@5（500 字） | ~~1.000~~ | **0.549** |
| MRR@5（500 字） | 0.967 | **0.715** |

加 4 篇干扰文档是刻意设计：无干扰时 12 篇 / 30 chunk，k=10 就占 1/3 库；加干扰后 20 篇 / 37 chunk，top-k 才有区分度。

## 2. 切片粒度不是越大越好，也不是越小越好

500 字切片（37 chunk）、仅向量检索（TF-IDF）：

| 指标 | k=3 | k=5 | k=10 |
|---|---|---|---|
| HitRate | 0.921 | **0.974** | 1.000 |
| Recall | 0.433 | **0.549** | 0.698 |
| MRR | 0.702 | **0.715** | 0.719 |
| Precision | 0.404 | 0.316 | 0.216 |

三档切片在 k=5 的对比：

| 切片 | chunk 数 | HitRate@5 | Recall@5 | MRR@5 |
|---|---|---|---|---|
| 200 字 | 83 | 1.000 | 0.254 | 0.650 |
| 300 字 | 56 | 0.947 | 0.352 | 0.587 |
| **500 字** | **37** | **0.974** | **0.549** | **0.715** |

**结论（与 v1 方向一致，但原因完全不同）**：切片越小 HitRate 越高（更容易「碰到」相关文档），但 Recall 和 MRR 显著下降——知识点被切碎，同一问题的相关片段散落在多个 chunk 里，命中一个不等于召回齐全。v1 是 chunk 太少导致饱和，v2 是真实的碎片化代价。**500 字在三个指标上综合最优，200 字最差**。生产建议：按语义单元切片 + 句边界 + overlap，别只调字数。

## 3. 重排序（rerank）的价值在双阶段架构，但这次没证明出来

理想形态：

```
第一层：向量语义召回（embedding / Milvus）—— 对近义表述敏感，易召回噪声
第二层：cross-encoder 精排（bge-reranker-v2-m3）—— 按「查询-片段」真实相关性重排
```

而本项目当前实现是 **TF-IDF 召回 + BM25 精排，两者同源**（都是词频模型）。实测 500 字切片：

- MRR@5 从 0.715 → **0.738**（+2.3 点），MRR@10 从 0.719 → 0.742，稳定但微小；
- **HitRate@3 反而从 0.921 降到 0.895**：BM25 交互项有时把正确文档挤下去；
- Recall / Precision 小幅下降；alpha 从 0.0 调到 0.9 排序几乎不变。
- 根因：BM25 分与余弦分量纲差约 30 倍，alpha 实际近乎失效。

**这不是缺陷披露，是结论**：同源精排不可能带来数量级提升。它只能证明「重排不会显著变差」，证明不了「重排有效」。要释放 rerank 的价值，得把第一阶段换成 `bge-small-zh-v1.5` + faiss 语义召回、第二阶段换 cross-encoder —— 这是报告里写明的下一步，而不是含糊带过「rerank 通常提升 5%–15%」。

## 4. 未命中分析比平均分更有信息量

38 题中仅 1 题（D03「糖尿病眼底病变要达到什么分期」）在 HitRate@5 未命中：

- gold = `糖尿病__02_认定条件组合`（原文 D-4：视网膜病变 II 期及以上等）；
- 实际 top1 落在 `糖尿病__03_认定注意事项`（「须提供并发症佐证」这句概括因词语覆盖度高，把具体分期条款挤了下去）。

概括性文档抢夺细节性文档的排名，是精确条款检索的典型难点。解法是标题 / 条款号加权或二级精排，**不是继续加数据**。

## 5. 量化评估是 AI 工程师的标配

不靠「感觉 RAG 变好了」：固定题库、每次改动（切片、top-k、rerank）都出一组对比数字，并显式处理边界。`rag_core/eval.py` 重写四个指标，`tests_eval.py` 覆盖 **20 项断言全部通过**（空 gold / k≤0 / k 大于候选数 / 空候选 / 单文档多 chunk 展开为 chunk 级集合）。

复现：

```bash
cd preaudit-rag-engine
python build_corpus.py    # 从真实 xlsx / html 重建语料
python run_eval.py        # 三档 k × 三档切片，写 data/eval_result_v2.json
python tests_eval.py      # 20 项边界断言
```

完整报告、逐题明细与旧结论撤回清单见仓库 [`RESULTS.md`](https://github.com/symQWEQW/preaudit-rag-engine/blob/master/RESULTS.md)。
